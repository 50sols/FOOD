# #4375 — Archived store-role notification audience scope

- **Source:** P031 under #2782 / #2503. **Integration:** Foodex_V2 only.
- **Defect:** `NotificationAudience::context()` copied all historical `user_store_roles.store_id` values into notification matching, including assignments whose roles were archived while `is_active` remained true. A stale authenticated user could still match a store-targeted notification after role revocation.
- **Patch:** Preserve the existing sources (B2C customer enrollment, authorized DriverTenantScope, selected VanRuntimeContext, OperationalTenantScope dashboard permission, owned B2B orders) and constrain only the historical dashboard assignment source to an active, non-archived, store-scoped role and active B2C store.
- **Tests:** Seeded real DB service matching: active assignment positive, foreign store negative; archiving the role without flipping `is_active` immediately revokes store targeting for both stale and fresh actor; unrelated active retail assignment remains permitted; audit log is not mutated.
- **Review risk:** HIGH (confidentiality / tenant scoping). No schema, user records, permission grants, notifications, API route, UI or migrations changed. The service is shared with app notifications, but no mobile source/API contract, login, Van B2B or Driver B2C fulfillment changes; Customer / Driver / Van each keep their independent source projections. This is a revocation correction, not a change to valid customer/driver/van targeting.
- **Limitations:** Does not claim atomic revocation across concurrent notification publication transactions, complete notification platform certification, or resolution of distinct dashboard-app audience classification. Directly targeted user notifications remain governed by existing published/eligibility checks. Follow-on comprehensive security acceptance stays on #2782 / #2503.
- **Merge gate:** Full final-head Repository Policy, V2 Isolation and Required CI including Laravel shards/MySQL Redis; per-file HIGH technical review; SHA-guarded squash merge into Foodex_V2 and verified closeout. No main, release, tagging or production.
