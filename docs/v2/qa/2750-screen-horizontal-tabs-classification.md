## Classification / acceptance contract
Every **page/screen** uses one decision:
- `CONVERT_TO_HORIZONTAL_TABS`: substantial, independent, revisitable sibling workspace areas. These are **audit candidates**; the original owning Issue/PR must verify semantic independence, permission/store scoping and contextual URL/POST preservation before authorizing implementation.
- `KEEP_EXISTING_TABS`: already has page-level navigation, including existing custom nav where directly inspected. Static code evidence alone does **not** certify ARIA/keyboard/RTL responsiveness.
- `NO_TABS_SINGLE_FLOW`: overview, customer storefront, coherent record details, inline subcomponent, context-dependent forms, app shell/navigation or one continuous operation.
- `SKIP_SECURITY/LOGIN/WIZARD`: login/auth, privileged security controls, risky update/recovery operations and sequential checkout/approval/stepper/wizard; do not hide critical confirmations behind tabs.

For later authorized changes, reuse `.foodex-tabs/.foodex-tab` before creating a new primitive; one row, contained horizontal scroll, short header, exactly one active panel, strict validated `tab` query, safe filter/search/pagination and POST redirects, AR/EN RTL/LTR, native keyboard and visible focus, server route/role/tenant and maker/checker. Do not copy arbitrary HTML. Shared source is under the canonical UI/UX contracts. **Existing issue #3947 PR #3948 is already merged** at `f3597e2df27298994bd9a68006e5f65d02039a72` (merge commit) and Action Center now classifies `KEEP_EXISTING_TABS`.
